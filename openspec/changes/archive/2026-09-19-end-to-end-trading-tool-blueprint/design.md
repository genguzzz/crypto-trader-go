## Context

独立新仓库只有阶段 1 的高层调研，尚无原型/Go 代码。用户需要可逐条审查和后续实施的完整方案。原有分数示例、Top200/12h 与“每 5 秒请求榜单”之间存在需要明确的时钟/覆盖率约束；仅凭一个库名列表无法决定集成。旧 `cryptoBot` 是只读参考，绝不迁移其凭据/实现。

## Goals / Non-Goals

**Goals:** 逐功能追踪需求→数据→处理→API/交互→降级→验收；解释行情聚合和候选池的资源预算；明确三类排序分/退出风险；给可验证的 Go 库选择矩阵和架构选型；规划原型和实现的依赖顺序。

**Non-Goals:** 不实现原型、Go 代码或数据库，不接账户，不自动下单，不宣称未回测的规则有统计优势，不替用户操作交易，也不以未经验证的第三方字段填充 UI。

## Decisions

1. **总览 + 专题蓝图，不把所有内容挤到一篇。** `docs/blueprint/README.md` 是导航和决策摘要；`feature-traceability.md` 逐功能矩阵；`runtime-and-data-contracts.md` 给事件、状态、库表、API、时钟、容量预算；`scoring-and-validation.md` 给因子、解释、回测和退出模型；`oss-and-data-sources.md` 给官方源/第三方、GitHub 库决策及 PoC 验收。根 `README`/`AGENTS` 只存入口和不变量。
2. **分钟完整性与五秒发现分开。** Top200 默认按所有 live USDT 普通永续的连续 720 根 confirmed 1m quote turnover 排序，>1000 万 USDT；每 5 秒合并全量 ticker 请求与 WS 缓存做成员发布，但确认版的 12h 交易额只随分钟收盘改变。每 5 秒的盘中评分标 `preview`，收盘评分标 `confirmed`；缺口/时间戳倒退/初始预热不得输出“精确可用”排名。新币无 12h 历史进入单独观察栏。
3. **闭环而非单一高分。** 公开数据覆盖圈选→条件门控→多空分别评分及解释/可信度→UI 审核→离线重放/样本外验证→只读仓位离场研究。自动执行永远是后续单独项目决策，不能由高分直接联动。
4. **Go 侧拥有域逻辑，第三方仅作边界库。** OKX 适配器通过窄接口可替换 SDK，第三方指标/图表/存储不定义分数语义。比较 API 覆盖、许可、维护和真实断线恢复 PoC 后锁版本；不一次性引入 AGPL 大型框架/多服务以免丧失控制。
5. **账户/外部内容分别隔离。** 新闻、解锁、链上持有人按来源发布时间和 symbol↔token/chain 映射，灰度/缺失不倒推历史；仓位属于私有域，原型只用合成记录，实施时需要最小读权限与防泄漏审计。

## Risks / Trade-offs

- **[风险] 全池 1m WS 订阅和 REST backfill 性能未经测量。** → 写出负载预算、指标和分片 PoC，若超过预算允许缩短/分层扫描，但必须明确 5 秒不能保证精确覆盖全池。
- **[风险] 数据因子覆盖率不同导致榜单不可比。** → 固定核心模型特征/权重与最低覆盖率；可选现货/逐笔/外部事件做单独标签或增强版，不在同榜单偷偷混公式。
- **[风险] 开源 README “支持 OKX”不代表 USDT 永续所有 endpoint 可用。** → 功能级 PoC 与精确许可核查，达标再选，不把未验证宣传当事实。
- **[风险] 学术研究变量与扣成本实盘表现不同。** → 当时可见样本、市场状态、样本外、成本、消融与 forward shadow 作为进场研究门槛。
- **[风险] 历史归档错误传播。** → 新文档显式 supersedes 第一版粗略方案中的可变决定；不改旧归档本身。

## Migration Plan

在新仓库新增本变更下的文档与一个导航入口；更新根上下文指向深度蓝图；检查内部链接、官方源可达性及 OpenSpec strict validate；只归档研究补充 change。原型/实现另建 change，决策变化须 ADR/版本化，且仓位访问/下单分别审批。

## Open Questions

“热门”是 12h USDT 成交额还是 OKX 官方热门榜；5 秒是否只要求名单核对或逐笔精确 12h；需要多大历史保留/一台机器/同一家庭设备远程访问；只读账户何时授权；新闻/解锁第三方订阅预算；最终评分目标周期、风险预算和提醒阈值。均给可逆默认值，不堵塞文档研究。
