## Context

旧仓库 `/Users/gugen/Code/cryptoBot` 的 2026-09-12 Python/Top100/24h 方案和 `ob_os_monitor_bot` 仅可作为口径/探针的历史对照，但用户已选择新的 Go 优先、Top200、12h 交易额、多空机会与只读仓位研究方向。本变更仅产出决策、调研报告和项目级提示，不迁移旧代码，也不声明候选公式有盈利能力。阶段 2 与阶段 3 使用独立 OpenSpec change。

## Goals / Non-Goals

**Goals:** 明确 OKX 官方与第三方数据边界；可配置的滚动 12h USDT 候选池口径；约五秒名单协调和实时 WS 更新的区别；Go/开源框架取舍；独立多空入场、持仓离场评分的可解释研究协议；桌面/手机交互信息架构与交付顺序。

**Non-Goals:** 不实现原型、Go 服务、账户授权或下单；不读取私有凭据；不声称“假成交量”“巨鲸操盘”可由单一指标识别；不保证五秒粒度的逐笔精确 12h 滑窗。

## Decisions

1. **Go 模块化单体，而非复刻 Python 服务或套入大型机器人框架。** 下一阶段后拟划分 `exchange/okx`、`universe`、`marketdata`、`feature`、`score`、`portfolio`、`api`。可参考旧仓库 Vue/TS + Lightweight Charts 的 UI 思路；旧 Python/Freqtrade 仅作研究对照，不作为新平台线上数据真源。对比 GoCryptoTrader、BBGO/Banbot、专用 OKX SDK 后才决定适配层依赖；引入 AGPL 组件须审查再用。备选 Python：已有资产多，但当前明确 Go 优先；不消灭 Python，避免同时维护两套线上评分公式。
2. **Universe = 所有 `state=live`、`settleCcy=USDT`、排除 `ruleType=pre_market` 的 `*-USDT-SWAP` → 截至同一基准分钟、连续无缺口的 720 根已确认 1m K 线的 `volCcyQuote`（USDT）→ 严格 `> threshold` → 交易额降序前 200。** 时间窗口是分钟粒度的近似滚动 12h，边界时刻可能差至 1 分钟；盘中 1m candle 仅作标注的 UI 预估，不能混作已确认成交额。启动时历史 K 线批量 backfill，直到全部候选数据完整前标记 `warming` 并暂不作精确排名。快速 ticker `volCcy24h * last` 仅用粗略发现，不代替 12h USDT 成交额。约每 5s 协调已缓存数据与 REST 全量 ticker 快照；WS K 线更新缓存，REST 做初始化/补洞；订阅池增删的错误不能让旧列表被误认为新鲜。备选全品种逐笔 12h：成本和存储过高，仅在确实要求逐秒精度时评估。
3. **事件分层与数据质量契约。** 公共 REST instruments/tickers/candles、WS tickers/candle/open-interest（频道实测后确认）分别进有界队列；统一 `instrument`, `exchange_ts`, `receive_ts`, `source`, `units`, `confirmed`, `sequence`, `freshness`。同源时戳倒退拒收，断线退避重连并补洞；OI 优先使用 OKX 的 `oiCcy` 标的币数量；只有张数时才按合约规格 `ctVal/ctValCcy` 转换，绝不把 OI 名义美元上涨简单算作新开仓。OI、资金费率、现货/永续差异要分别附来源和时间戳。OKX 不提供的解锁、新闻、链上持有人归类必须第三方对接，并区分“缺失/未知/待核实”。
4. **评分先研究后校准。** 将市场可交易性与数据新鲜度设硬门槛，独立计算 0–100 的 long/short entry，展示对称证据项、方向性成本/拥挤惩罚、缺失特征与质量标签。只用当时可见快照；参数版本固定、增量反事实/消融与时间滚动样本外评估。仓位 long/short exit 是独立的保护/衰弱/事件模型，不从入场分机械反推；风控警报不受综合分“补偿”。简单加性可解释模型是 v0，对高度相关特征分组限权、防止重复累加；未来乘法只用于明确的质量门控，需先有数据支持。备选 ML 黑箱排名：当前无训练数据、标签和验证，暂缓。
5. **只读账户权限与产品分面。** 阶段 2 仅合成持仓；阶段 3 后期账户连接单独评审只读 API key、IP 约束与最小权限、隐私日志。个人仓位可展示盈亏、强平距离和独立离场建议的依据，但不自动下单。桌面为扫描列表/详情并排，移动为列表路由→详情路由，仓位另设页面；图表用独立本币价格 K 线和锚定时刻归一到 100 的跨资产对比，避免把 BTC 与低价币的绝对价格叠加误读。

## Risks / Trade-offs

- **[风险] 5s 更新被误解为 5s 精确 12h 成交额。** → UI 同时标示名单协调时刻、末根确认 K 线时刻和不完整/预热状态；如需秒级精确需补逐笔流水与负载测试。
- **[风险] 每 5s 从 400+ 合约请求多种 REST 端点超限。** → 仅全量 ticker 使用低成本轮询，其他资料共享 WS、分段 backfill 和限流队列；按最新官方配额压测。全量 ticker 实际使用仍可调节周期。
- **[风险] OI/量价方向的非因果解释与存活偏差。** → 特征分开标注“观测/假设/验证”；捕获上市、退市、下架及当时可用的历史池，成本后按品种/时段做 walk-forward。
- **[风险] 第三方解锁/链上归因错映射。** → 来源与发布时间、地址/chain 映射和归因置信度独立呈现，未知不记为零风险。
- **[风险] 旧工作区存在未提交用户改动及隐藏配置。** → 不覆盖旧代码/文档，不读取 secret，新增本 change 下隔离文档并检查 diff。
