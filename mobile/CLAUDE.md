# OKX Helper (native iOS) — working rules

Native iOS client of OKX Helper (ctg). Lives in `mobile/` on branch **`ios`**; the Go backend and the Vue web app stay on `main`. Same stack and conventions as mediahub/Murmur: Expo SDK 58, React Native 0.88, Expo Router, `NativeTabs` (system tab bar → Liquid Glass on iOS 26), left drawer, expo-updates against our own server. Runs side by side with the Capacitor app (`web/ios`, bundle `top.gugenzzz.ctg`): this one is `top.gugenzzz.okxhelper`, display name `OKX Helper`, its own runtime versions. Most new requirements target this client. Read `AGENTS.md` (Expo: don't trust memory, check versioned docs).

## Architecture

```
iPhone OKX Helper ──HTTPS──▶ ctg.gugenzzz.top (ctg-prod nginx → ctg :8686)
   REST /api/v1/* (same routes as web/src/api.ts)      SSE /api/v1/stream (expo/fetch streaming)
   WebView /embed/chart/:id (web PriceChart, no chrome) Expo Updates /api/v1/expo/manifest + /assets
   POST /api/v1/app/events (usage) · /api/v1/app/logs          (all /api/v1 needs the owner key; OTA is public)
```

- Backend pieces are shared: change them on `main` (main checkout, small commits), then `git merge main` into `ios`. Before every push to `main` check `curl -s https://ctg.gugenzzz.top/api/v1/ai/busy` says `{"running":false}` (a push deploys and restarts the server). Never force-push `main`.
- Server side of the app: `internal/api/mobile.go` (OTA, events, logs; data in `/opt/ctg/data/mobile/` on ctg-prod = `/data/mobile` in the container) and `web/src/views/EmbedChart.vue`.
- Owner key (`X-CTG-Admin`) is required for every `/api/v1` call except health/status, `ai/busy` and the Expo OTA routes (server `internal/api/admin.go`). `lib/adminKey.ts` keeps it in the keychain; `components/KeyGate.tsx` (full screen, 输入访问密钥, verified against `/api/v1/settings`) opens when none is stored or any call gets 401 `admin_required` (`keyRejected`: the bad key is cleared, waiting calls retry once with the new one). Every network path sends it: `req`, AI `kfetch`, the SSE stream, `CoinIcon` (expo-image `headers`), and both WebViews (`keyScript` → `window.ctgAdminKey` before load; the web page adds it to every request; the WebView is keyed by the key). Settings → 访问密钥 changes or clears it. The web preview passes `?key=` (stream, icons only).

## Ship it

- Before every commit: `cd mobile && npx tsc --noEmit && npx eslint src`. Commit to `ios` and push.
- JS-only change → `mobile/scripts/ota.sh "说明"` (~1 min): export, ssh-copy into `data/mobile/updates/<runtime>/<uuid>/`, verifies the manifest serves it. Roll back by deleting the newest dir there. Check what phones ask for: `ssh ctg-prod 'docker logs ctg 2>&1 | grep "expo manifest" | tail'` (`runtime`, `current` → `served`).
- Native change (new/upgraded native package, config plugin, permission, SDK) → bump `RUNTIME_VERSION` in `app.config.ts`, then `mobile/scripts/release.sh X.Y.Z "新增：…；修复：…"`. The tag `m-vX.Y.Z` runs `.github/workflows/mobile-ios.yml` (image `xcode-27`, ~15 min, free: public repo): GitHub Release + publish to the 全能签 source through Murmur's publisher on ctg-prod (deploy key from environment `production`, token read on the server). Pushes to `ios` touching `mobile/**` build only (artifact). Verify: `curl -s https://apps.gugenzzz.top/appstore.json | grep okxhelper`.
- Swift can't build on tutu; native changes are verified only by CI. Push them alone first, watch with `gh run watch <id>` in the background.
- Web preview: `npx expo export --platform web --output-dir dist-web`, serve with SPA fallback and `/api/*` proxied to production (on web `API_ORIGIN` is same-origin), screenshot with Playwright (Chromium needs `--proxy-server=http://127.0.0.1:7080` for the chart iframe). Tabs render on top on web.

## App conventions

- Tabs (`src/app/(tabs)`): 扫描 · 交易 (自选 is a chip in 扫描; the AI is the floating orb). Drawer (`components/Drawer.tsx`; menu button in `TabHeader` or left-edge swipe): 规则与战绩, 监控告警, 系统状态, 帮助, 设置, Dev. Pushed screens use `TopBar`; settings is a modal; `/chart/[id]` is a full-screen landscape modal. Pages not built yet use `Placeholder` (what will come + open the web page).
- Interactions and looks follow the web app: tokens in `lib/theme.ts` mirror `web/src/style.css` (black canvas, lime `#bcff2f` accent, up `#25a750`, down `#ca3f64`); number/time strings come from `lib/fmt.ts` (port of `web/src/fmt.ts`, display zone default UTC+8); types in `lib/api.ts` mirror `web/src/api.ts`. When the web changes a definition, port it.
- K-line chart = the web chart in a WebView (`components/ChartView.tsx` → `/embed/chart/:id?spot=&oi=&bar=&layer=&full=`). Don't rebuild it natively. While a finger is on it the page scroll is locked; full-screen button posts `fullscreen` → `/chart/[id]`. Small secondary charts use `components/Charts.tsx` (SVG `LineChart` / `BarChart`).
- Data: `useQuery(key, fn, {interval, staleMs})` from `lib/query.ts` (shared cache, persisted, polls only while focused and active); `mutate`/`load` after actions. Market data in `lib/market.ts`: `useMeta`, `useUniverse` (15 s poll + stream-triggered refetch), `useLivePrice` (SSE `prices`), `toggleWatch` (optimistic), `useRuleId`.
- Pull-to-refresh: `<Pull onRefresh>`. Every tap gets haptics (`tap()`), results `toast()` / `toastError()`, destructive actions `confirm()`. UI copy Simplified Chinese, plain and precise, no emoji or exclamation marks.
- Device features only through `lib/device.ts` (`has(capability)` first — OTA code can run on an older binary). Runtime 1 ships the capability pack: glass, haptics, blur, symbols, secure-store, sqlite, local notifications, speech recognition, audio recording (microphone permission for AI voice), clipboard, sharing, linking, web-browser, WebView, network, keep-awake, quick actions, Face ID, orientation. Settings → 能力自检 exercises them.
- Drawer pages (phase 2b): `rules/index.tsx` + `rules/[id].tsx` (track record, weight editor), `alerts.tsx`, `status.tsx` (3 s poll while focused), `help/index.tsx` + `help/[slug].tsx`, `settings.tsx` (+ `components/settings/*`: server settings with a save bar, interaction channel, AI authorization, developer), `dev.tsx` (keys, access, request log, endpoint reference, tester calling `/api/open/v1` with a pasted/just-created key; the drawer entry hides via Settings → 开发者 → 显示 Dev 入口). Their endpoints/types live in `lib/sysApi.ts` (port from web `api.ts`/`tradeApi.ts`). Shared form bits in `components/Form.tsx`: `Field`, `Input`, `NumInput`, `Toggle`, `Meter`, `SectionHead`, and `InfoTip` (web ⓘ → bottom sheet; rich text with `P`/`B`/`Code`). Copy the web page's tip text verbatim.
- Help articles: `node scripts/gen-docs.mjs` bundles `web/src/docs/strategy/*.md` into `src/content/strategyDocs.ts` and `web/src/docs/sdk.json` into `src/content/sdkRef.ts` (API 参考, `components/ApiRef.tsx`, slug `api`) — generated, commit them; rerun after the web docs change. Strategy examples get 「在编辑器中打开」 (creates a draft → `/trading/strategy?source=`). `components/Markdown.tsx` renders them (headings, lists, tables, quotes, code blocks with copy and Python highlighting; no HTML). Links `/help/strategy/x` stay in the app, other paths open the web.
- Logging: `logger("area")` (ids, counts, timings, errors; never keys). Settings → 上传日志 → `data/mobile/logs/<id>.log`. Usage events: `track(name, props)` → `data/mobile/events/YYYY-MM-DD.jsonl`.

## AI (floating orb + sheet, `src/app/ai.tsx`)

- The AI is not a tab: `components/ai/FloatingOrb.tsx` (rendered by the root layout over every screen, hidden on /ai, /chart, settings, diagnostics) floats centred above the tab bar. Tap → `router.push("/ai")`, a `formSheet` (detents 0.65/1); on an instrument page the coin becomes the context (`setContext`, the chat stays). Press and hold → `useHoldToTalk` (waveform capsule, slide up to cancel), the text is sent and the sheet opens. A satellite circles it while an answer runs; an orange dot marks an unread answer. `initAi()` and the 「AI 回答好了」 toast live in the root layout. ai-history / ai-notes are modals so they stack above the sheet.

- Port of the web assistant (`web/src/composables/ai.ts`, `components/ai/*`); backend `internal/aigate` (chat.go, http.go, notes.go). When the web changes, port it here.
- `lib/ai.ts`: one global chat store (`useAi()` re-renders per event, text deltas batched to 60 ms; `useAiSelect(pick)` for one value, e.g. the tab badge). POST `/api/v1/ai/chat` → SSE read through `expo/fetch` (real streaming body on iOS; plain fetch on web). Same connection logic as the web: `stream` (40 s silence watchdog, server pings every 15 s) / `sync` / `reconnect` (backoff 1 s→15 s, only while active) / `resume` (AppState active, expo-network back, tab focus). `syncSeq` makes older loads give way. Device keys (SecureStore; localStorage on web): `okxh.aiChat`, `okxh.aiPending`, `okxh.aiModel`.
- `initAi()` runs from the tabs layout (resumes a running chat at app start). An answer that finishes while the tab is hidden sets `unread` (tab badge 新 + toast 查看); in background it also calls `notify()`.
- All AI calls go through `kfetch` (owner key header; 401 `admin_required` → KeyGate, then one retry).
- Rendering: `components/ai/Markdown.tsx` (markdown-it → RN; app paths become lime chips mapped by `appRoute()`: `/instrument/X`, `/rules/<id>` → `/rules?id=`, `/trading*` → `/trade`, `/alerts`, `/status`, `/settings`, `/help*`, `/`; other links → in-app browser), `blocks.ts` (fenced JSON blocks, same as web), `AiBlock.tsx`, `AiSteps.tsx`, `Orb.tsx` (SVG gradient, no expo-linear-gradient).
- Voice (`lib/voice.ts`): expo-audio recorder (m4a, metering → waveform) loaded lazily behind `has("audio")`; upload as multipart `audio` to `/api/v1/ai/transcribe`. Composer mic = tap to start / tap to send / ✕ cancel; the hello orb = hold to talk (slide up to cancel). The system tab bar can't take a long-press, so there is no hold-to-talk on the AI tab button.
- Instrument page → 问 AI: `askAbout(id)` (starts a fresh chat unless one is running) + `router.navigate("/ai")`; the context chip in the composer clears it. History and memory are pushed screens (`app/ai-history.tsx`, `app/ai-notes.tsx`).
- AI trade proposals (owner only, `lib/realtrade.ts`, `components/ai/ProposalCard.tsx`): the MCP tool `propose_trade` creates a pending real-OKX order (market + TP/SL, isolated; DRY RUN until the server is switched to live). A tool step whose output has `proposalId` gets a live card under it (同意 asks with the exact order, POST `via: "app"`; 409 = answered elsewhere → final state); the 交易提议 pane (header button, `/ai?pane=trades`) lists pending then recent; count badge on the orb, toast on a new one. Refetch on stream event `realtrade` and foreground. The card's K-line is a floating `ChartView proposal=<id>` (`/embed/chart/:id?proposal=` draws entry/SL/TP) inside the AI sheet, not a Modal.
- Test streaming against production with tiny questions (你好); the owner key only from `ssh ctg-prod 'grep ^CTG_ADMIN_KEY= /opt/ctg/ctg.env'` into an env var, never printed.

## 交易 tab (paper trading, port of web views/trading/*)

- `app/(tabs)/trade.tsx`: segmented sub-navigation 账户 · 策略库 · 待确认 · AI 决策 (`?pane=accounts|strategies|prompts|ai`), one pane each in `components/trade/*Pane.tsx`. Pushed screens: `trading/account/[id]` (KPIs, explorer, 持仓/委托/历史/成交/流水, instances, signals, 入金 / 风控 / 全部平仓 / 归档), `trading/backtest/[id]` (report), `trading/new` (4-step wizard; `?mode=backtest&strategy=` / `?from=<accountId>`), `trading/strategy?version=|source=` (native editor: coloured CodeView, tap a line to edit in a monospace TextInput with a key row; draft autosave, check, publish; 试运行 + 结果 tabs with a native TrialChart).
- API + types: `lib/tradeApi.ts` (web/src/tradeApi.ts); labels, formatting, validation: `lib/tradeMeta.ts` (web components/trade/meta.ts + tradeMeta.ts — keep the Chinese copy identical); strategy templates `lib/strategyTemplates.ts` (copy of web editor/templates.ts). Owner-key writes (sources, check, trial, AI memory reflect) go through `req` like everything else.
- Live refresh: `lib/tradeLive.ts` — `useTradeEvents` (stream `trade` / `interact` events via `market.onStreamEvent`, focused screens only) and `useOpenPrompts` (30 s poll + `interact` events) → badge on the 交易 tab (`NativeTabs.Trigger.Badge`) and on 待确认.
- Charts: 组合视角 is native SVG (`trade/EquityTradesChart.tsx`, port of web EquityTradesChart + tradeMarks: bubbles, groups → zoom, legend with open positions, pinch zoom; full screen = RN `Modal` in TradeExplorer); 币对视角 is the web `TradeCandleChart` in a WebView: `/embed/trades/:accountId?inst=&trade=` (web `views/EmbedTrades.vue`, lives on `main`). The app selects a trade with `injectJavaScript("window.ctgSelect(id)")`; the page posts `{type:'pick', ids}`. Key the view by instrument (another instrument = fresh page).
- InfoTip text from the web is an (i) button → sheet (`components/trade/common.tsx InfoTip`). Forms with inputs use `FormSheet` (keyboard-avoiding), not `Sheet`.
- Testing: never write to production from previews (no accounts, instance actions, answers, publishes). The preview server should proxy GET only.

## Traps

- Number inputs inside rows: RN-web gives `TextInput` an intrinsic width; `NumInput` sets `minWidth: 0` so values don't render outside the box.
- The web preview server must block non-GET `/api/*` (read-only checks against production).
- `react-native-webview` 14 types `WebView` as `never` under strict TS; `ChartView.tsx` casts it to `ComponentType<WebViewProps>`.
- Header values must be ASCII (fetch throws otherwise); `api.ts` strips non-ASCII from `x-app-version`.
- An OTA only reaches binaries with the same runtime. If a runtime bump's IPA never got built, phones stay on the old runtime and see nothing.
- The scanner list freezes its order while dragging/momentum (like the web), so taps land on the intended row.
