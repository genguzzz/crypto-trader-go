# 事实面板、规则分与战绩

实时定义以 MCP 为准：`list_fields`（字段 key、名称、单位、公式）、`list_rules`（规则权重与门槛）、`get_rule_track_record`（战绩）、`get_universe` / `get_instrument`（当前值、分位、分数）。

## 事实面板（因子）

无方向的客观测量；实时与历史回放用同一公式。“仅实时”= 历史回放里没有（不可回放）。

| key | 名称 | 单位 | 定义 |
|---|---|---|---|
| `ret_15m` / `ret_1h` / `ret_4h` / `ret_24h` | 涨跌 | log | 永续收盘对数收益（15m 仅实时） |
| `excess_btc_4h` | 相对 BTC 4h | log | ret_4h − BTC-USDT-SWAP 同期收益 |
| `trend_z_4h` | 4h 趋势强度 | z | ret_4h ÷ (过去 48 根 1H 收益标准差 × √4) |
| `trend_ema` | EMA 趋势 | z | (EMA8 − EMA24)（1H 收盘）÷ 价格 ÷ 1H 收益标准差 |
| `eff_ratio_24h` | 趋势效率 24h | 0–1 | \|24h 净变动\| ÷ 24 根 1H 变动绝对值之和；1 = 单边，0 = 来回震荡 |
| `beta_btc_48h` | BTC β 48h | 倍 | 48 根 1H 对数收益对 BTC 的回归斜率 |
| `resid_15m` / `resid_1h` / `resid_4h` | 残差收益 | log | 收益 − β × BTC 同期收益（剔除大盘带动；15m 仅实时） |
| `oi_chg_1h` / `oi_chg_4h` | OI 变化 | log | 币本位持仓量 oiCcy 的对数变化（排除价格导致的 USD 持仓变化） |
| `vol_surprise_4h` | 放量 4h | log | log(近 4h USDT 成交额 ÷ 过去 7 天 42 个 4h 成交额中位数)；界面显示倍数 |
| `funding_hourly` | 资金费/小时 | rate/h | 最近一次已结算资金费 ÷ 结算间隔小时（4h/8h 已换算） |
| `funding_pred_hourly` | 预测资金费/小时 | rate/h | 当前周期预测资金费 ÷ 间隔小时（仅实时） |
| `basis` | 期现基差 | log | log(永续价 / OKX 同名 USDT 现货价)；无现货 = 未知（仅实时） |
| `spread_bps` | 点差 | bps | (ask − bid) / mid（仅实时，门槛用） |
| `turnover12h` | 12h 成交额 | USDT | 720 根已确认 1m 的 volCcyQuote 之和（不进分位打分） |

**单位换算（重要）**：
- API/MCP 里 `log` 字段是自然对数。界面显示为简单百分比 = (e^v − 1) × 100%；小幅度时两者几乎相等。例：v = 0.0953 → +10%。
- `vol_surprise_4h` 界面显示 ×e^v（例 v = 0.693 → ×2.00）。
- `funding_hourly` 是每小时的比率：0.0001 = 0.01%/h（≈ 0.08%/8h）。界面显示 ×100 保留 4 位，如 `0.0100%/h`。MCP `get_series field=funding` 返回的是**每次结算**的费率，不是每小时。
- 资金费正值 = 多头付空头，负值反之。OKX 各合约结算间隔不同（4h/8h），跨币比较看每小时值。
- OI 增加只说明新开仓多于平仓，**不能**说明是多头还是空头在加仓。

## 分位

每个字段在**当前活跃池**内排序得到分位 p ∈ [0, 100]（0 最低、100 最高，并列取中间名次）。API 里是 `pct`。只比较“同一时刻池内谁更强”，对极端值稳健，但丢失幅度信息。

## 规则分（多头分 / 空头分）

1. 分位 → ±1：x = 2·p/100 − 1（池内最高 +1、中位 0、最低 −1）。
2. **分数 = 50 + 50 × Σ(wᵢ·xᵢ) ÷ Σ|wᵢ|**，范围 0–100，50 中性。
3. 正权重 = 字段越高越加分；负权重 = 越低越加分；权重只看相对大小。
4. **多空独立**：各有一套权重，不要求相加为 100；多头分低不等于该做空。
5. **缺失 ⇒ 未评分**：任一加权字段缺失，该方向显示“—”，不补 0。新币/数据缺口常见。
6. **门槛（gate）**：目前是点差上限（bps，0 = 不限）。点差超过时标“门槛”（API `gate` = `BLOCKED:…`，通过为 `PASS`），分数照算但提示交易成本过高；分数再高也不能覆盖门槛。
7. 盘中每 10 秒按未收盘分钟预览（会变动）；每个整点为每条规则保存一次不可改写的快照，只有快照进战绩。

例：权重 多头 = 4h 趋势 0.45 + OI 变化 0.30 + 放量 0.25，三项分位 99/99/98 → x ≈ 0.98/0.98/0.96 → 多头 ≈ 98.7。

分数只是“候选排序”，不是胜率、不是下单建议；所有规则默认标“未验证”。

## 规则与战绩页 [规则与战绩](/rules)

- 左侧规则列表（自建 + 内置“对照”规则），右侧战绩，下方“编辑权重”。
- 编辑：每个字段填多头权重、空头权重，设点差门槛与说明。**保存 = 发布新版本（v+1）**：立即对当前池重新打分，后台重算历史回放，旧版本战绩保留。也可“另存为新规则”或删除。
- 含“不可回放”字段的规则无法做历史回放，只能积累上线后战绩。
- 默认规则在 [设置](/settings) → 评分规则里选；扫描页可临时切换。

**内置对照规则**（比较基准，不是推荐）：`resid-reversal` 残差反转（β 中性，默认规则）、`trend-oi-confirm` 趋势+OI 确认（旧方向，实测 IC 为负，留作对照）、`short-term-reversal` 短期反转（相对 BTC）、`funding-tilt` 资金费倾向、`ema-trend` 趋势跟随（EMA + 效率比）、`fast-resid-momentum` 快速残差动量（15m，仅实时）。链接写法如 [残差反转](/rules/resid-reversal)。

## 战绩怎么读

周期 1h / 4h / 24h，分两类样本：
- **上线后**：每个整点的真实快照，不可改写 = 样本外，最可信。
- **历史回放**：用 1H 数据按当时的监控池重算最近 14 天；只含现在仍上市的币（幸存者偏差），点差按 2 bps 假设，可能与设计规则时看过的数据重叠——只能参考。

| 指标 | 含义 |
|---|---|
| Rank IC | 同一时刻池内“分数排名”与“之后 h 小时实际收益排名”的 Spearman 相关，−1～1。0.02–0.05 在因子研究里已算有信号。空头 IC 用 −收益计算 |
| t 值 | IC 均值 ÷ 标准误；每周期只取不重叠截面（1h 每小时、4h 每 4 小时…）。\|t\| > 2 约等于 5% 显著 |
| 截面数 | 样本个数，少于 30 时结论为“样本不足” |
| 前 20% 超额（毛） | 分数最高五分之一的平均收益 − 池均值（相对能力） |
| 前 20% 净 | 前五分之一的绝对收益 − 双边 taker 5 bps×2 − 点差；包含整个池子的涨跌漂移 |
| 命中率 | API 字段 `longHit` / `shortHit`（不重叠截面上的命中比例） |
| 累计 IC 曲线 | 多头累计 IC：持续向上 = 稳定有效，向下 = 方向反了 |

**结论标签**：`样本不足`（< 30 截面）、`有初步证据（仍需更长样本）`（≥30 截面、t > 2 且扣费后为正）、`方向相反（显著为负）`、`无显著证据`。

解读要点：看上线后样本优先；IC 小但 t 显著才有意义；扣费后为负的规则即使 IC 为正也难以交易；多次试参数会产生假阳性（过拟合）。
