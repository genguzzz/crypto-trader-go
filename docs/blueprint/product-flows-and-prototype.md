# 页面信息架构与阶段 2 原型验收稿

> 本文是**原型设计输入**，不是已制作的可点击原型。采用合成、可重复的数据集，先解决“很多信息怎么能看懂”。运行与 API 定义见[运行契约](runtime-and-data-contracts.md)，逐项数据/失败情形见[功能矩阵](feature-traceability.md)。

## 1. 主任务流：发现 → 核验 → 观察/仓位

1. **筛选**：用户打开 `/scanner`，先看到 `ACTIVE n/200`、筛选口径 `12h >1000万 USDT`、`asOfMinute`、系统延迟与预热数；选择 `全部/做多/做空/自选/持仓`，高级筛选分数、funding、OI 变化、流动性、风险 tag。默认按对应**同版本核心分**排序；用户可改按成交额/涨跌/费率，不改 active 的算法资格。
2. **理解而非盲跟**：点列表 BTC-USDT-SWAP，保持左边当前位置，右侧独立详情路由 `/instrument/BTC-USDT-SWAP`。分数卡首屏给 `多头 63 / 空头 29` 的**示例合成值**、`confirmed/preview`、可信度、门控状态和“高分不是交易建议”。点击解释项查看 OI/价格/现货/费率的原始值、时间窗、对子分的加减分与来源。
3. **看图证伪**：第一张图本币合约 K 线（可叠本币现货，独立轴），第二张可选比较图以相同起点=100 的 BTC/ETH/该币相对表现；“大盘”选项仅用于另建可追溯的 OKX USDT 永续市场篮子，不能伪称全币市值指数；下部 OI/funding/basis 与 bar 的**相同时间轴**，标新闻/解锁发生**及当时公布**的不同时间。无现货报价时隐藏该系列并注明，而不是画 0。
4. **标记/提醒**：可以加到 watchlist；确认分若未来经验证后允许手动订阅提醒，提醒显示原因和有效期。只读阶段没有“立即买入”按钮，也不能从提示一键下单。
5. **看持仓**：用户手动点 `/positions`，未接账号显示未连接；接只读账号后显示净/双向、方向/张数/mark/估算强平/当前盈亏与组合敞口，点仓位开独立详情。仓位的**继续持有/应复核/保护**和核心入场分可并列但明确不是互相反推。

## 2. 桌面信息密度（两栏，适合大量合约）

```text
┌──────────────────────────────── 顶栏 ──────────────────────────────────┐
│ OKX 研究台 | 扫描器 | 我的仓位 | 规则实验 | 系统状态       last update 5s │
│ 活跃 137/200 · 12h >10m USDT · bar asOf 12:00 · WS green · warming 7    │
├─────────────────────────────┬───────────────────────────────────────────┤
│ 左：列表(可拖拽宽度、虚拟滚动)│ 右：BTC-USDT-SWAP (固定选中，不随重排消失)   │
│ 方向 [全部][多][空]          │ Last/Bid/Ask · 多63 / 空29 · confirmed     │
│ sort [核心规则分 ▾]          │ 状态：允许研究，不是可自动交易许可          │
│ filters: OIΔ / fee / risk    │ 分数拆解 [趋势 +][OI确认 +][拥挤 -][缺失 ?]│
│ BTC  多63 空29 vol12h ...    ├───────────────────────────────────────────┤
│ ETH  多58 空34 vol12h ...    │ K线 [swap][+spot] 1m 15m 1h 4h          │
│ NEW  warming（不计入Top200）│ 比较 [该币 BTC ETH] (base=100 at t0)     │
│ ...                          │ OI | funding next | mark/index | basis      │
│ [我持有的] 永远可选           │ 深度/成本 | 相关新闻 | 解锁/持有人来源     │
└─────────────────────────────┴───────────────────────────────────────────┘
```

- 第一屏只显示决策先决条件：状态/口径/方向核心分/风险/新鲜度。新闻和链上附加信息靠后展示，不让未验证的故事压过已知行情。
- 列表每行占位固定，异步消息只更新改变项，按排序节流更新位置；用户滚动/选中详情保持稳定。中断后 banner “历史缺口待补，不产生确认分”。
- **分数抽屉**：规则组→子因子→原始字段/标准化→方向贡献→数据更新时间、缺失、模型版本，示例公式和回测状态可以展开，不能只给一个不可解释的圆形分数。

## 3. 手机独立路由

```text
/scanner ──tap row──▶ /instrument/:instId
   │                     [概览] [图表] [因子] [事件/风险]
   │
   ├──[持仓]────────▶ /positions ─tap──▶ /positions/:key
   └──[状态]────────▶ /status
```

列表为卡片式紧凑行：币/USDT、方向分、12h volume、新鲜度与最重要的风险 tag；筛选/排序是折叠抽屉。点后进入独立详情页，保留列表滚动位置和过滤器（浏览器返回仍在原处）；图表全宽，指标和事件为不同 tab。仓位使用私有路由与独立认证，不在公共币种 URL 中传账户信息。关键交互在 360–430px 宽度和桌面大屏分别检查，不靠水平滚动读完核心信息。

## 4. 四类重要状态必须画出来

| 状态/合成 fixture | 用户看到什么 | API/数据行为 |
|---|---|---|
| `STARTING/WARMING` 首次只有部分 K 线 | “正在预热 455/464，当前榜单不是全池精确 Top200”；新币观察栏 | 后端 `coverage` 明示，不能提前编造全市场分数 |
| `LIVE + preview` 某币 OI/价更新，分钟未收盘 | 5s 刷新虚线盘中分，主确认分保留上次 as-of；允许切两者但 label 常显 | `isPreview` 与 `confirmed` 的 scoreVersion/时钟分离，原型模拟分数重绘 |
| `STALE/RECOVERING` 网络 20 秒中断后恢复 | 顶栏橙/红、旧值灰化注明来源时刻；新提醒暂停，恢复中补缺口进度 | 未补齐 1m，不输出看似精确的名单；恢复成功后 snapshot+reset |
| `UNKNOWN EXTERNAL` 新闻提供方超额/解锁无覆盖/链上地址映射不明 | 资料卡写“未知/未覆盖/仅链上地址统计”，不能画安全绿勾 | 不更改 core 榜单；事件 tag 带来源、修订/首次可见时间 |
| `ACCOUNT NOT CONNECTED` / `ACCOUNT LOST` | “未连接账号”/“持仓数据陈旧”，绝不是“当前空仓” | 私有 API 状态与空 `positions=[]` 区分，私人余额不进入公共 SSE |
| `SUSPENDED/DELISTED` | 合约详情可读但顶部强标不可新建风险；若已有仓位需独立追踪 | active 移除原因明确，自选/持仓不丢失 |

## 5. 规则实验与回放：比可配置权重更重要的扩展

用户希望有多种排序但最看重自己规则。只允许配置“阈值和有限白名单参数”仍不足以安全地迭代规则，故建议 I3 后增加**规则实验室**：

- 列出 `entry-core-v0`, `entry-spot-v0`, `exit-risk-v0` 的输入集合、窗口、权重、硬门槛、版本、训练/样本外日期；用户可复制一个版本做实验，但实验分在榜单上以“未验证”独立显示，不覆盖默认核心榜单。
- 配置编辑前显示“改变了什么、受影响品种与缺失率”，历史回放比较同一批候选、成本后的多空表现、单因子消融和最差阶段；公布尝试了多少个版本防止过拟合。**规则分的意义是有条件的研究排序，不是客观预测准确率。**
- 保存结果快照与事件输入 hash，选中某时刻可重放“当时为什么排第一”；线上分仅采同一 Go 核心，实验版本不得改写已发布历史数据。
- 此页面若暂缓实现，阶段 2 也应包含静态原型说明“当前分数未验证/如何看分解”，不能把权重滑条伪装成有效策略调参器。

## 6. 组合风险：仓位页独有的补充思路

仓位分析不能只看每个币的止盈止损。规划增加**组合敞口总览**：USDT 名义敞口、同向 BTC/ETH/高相关品种聚集、跨/逐仓保证金模式、估算剩余风险预算、资金费结算时间；对多个高度相关币同时“高做多分”不等于可同时加满仓。相关性以过去训练窗口估计并标不稳定性，不把它当精确预测。全仓强平估算依赖其他仓位及余额，界面优先展示交易所给出的 `liqPx` 并注明可能变化，**不自己用一个币的价预测整个账户的强平点**。

## 7. 原型验收脚本（阶段 2 新 change 执行）

1. 桌面左侧连续新增/移除 20 个币同时用户看同一详情，选中不跳转；方向过滤、按 12h 量和不同方向分排序结果稳定。
2. 对同一合约选择 spot overlay 与 BTC/ETH normalized comparison，能看清两个图各自轴/基点/缺口；spot 不可得只隐藏 spot，不影响合约 K 线。
3. 在 OI涨价涨和“涨很多/成交额大但 OI 不跟”的两种 fixture 中，展开每项分数贡献和风险 tag，确认无“庄家造假”“必然做空”的肯定句。
4. 模拟 WS 中断→REST 返回旧 `ts`→补洞成功；观察榜单和指标变灰、系统状态和恢复，而不是持续更新为绿色。
5. 仓位未连接、断开、净/双向仓位、现有仓位不在 active、强平价缺失/组合保证金四种状态均不会显示错误的“空仓/安全”。
6. 360px 与宽屏、键盘 tab/屏幕阅读器基本可用；业务核心无需滚动到页面最末端才知道数据已陈旧。
