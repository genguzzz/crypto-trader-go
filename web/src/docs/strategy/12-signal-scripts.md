# 脚本信号

内置的信号类型（价格、区间、字段、续涨风险、告警、时间、计划）够用时优先用它们。条件需要指标、多根 K 线或多个币一起判断时，用脚本：一个 `Condition` 类，和写策略用的是同一套 SDK。

```python
from ctg import Condition, Fire, ta


class AaveRsiReclaim(Condition):
    """AAVE 15m RSI 从 30 以下收回"""  # 一行说明，显示在信号卡片上

    instruments = ["AAVE-USDT-SWAP"]  # 最多 10 个合约
    timeframe = "15m"                 # 每根 15m K 线收盘时运行：1m 5m 15m 1H 4H
    lookback = 100                    # 每个合约给多少根历史 K 线（10–500）

    def check(self, ctx, bars):
        b = bars["AAVE-USDT-SWAP"]     # b.ts b.o b.h b.l b.c b.vol b.volq：numpy 数组，最新一根在最后
        rsi = ta.rsi(b.c, 14)
        hit = rsi[-2] < 30 <= rsi[-1]  # 上一根在 30 以下，这一根收回
        return Fire(hit, values={"rsi": rsi[-1]}, note=f"RSI {rsi[-1]:.1f}")
```

## check 返回什么

- `True` / `False`：成立 / 不成立。订阅只在从不成立变为成立时触发。
- `Fire(成立与否, values={...}, note="...")`：同上，再带最多 12 个数值和一行说明，触发时出现在 ⚡ 信号消息里，平时显示在信号的“最近检查”里。
- `None`：现在判断不了（比如数据不够）。不会触发，也不会打断“从不成立到成立”的判断。

`ctx.now` 是这根 K 线的收盘时间（毫秒），`ctx.bars(合约, n)` 取最后 n 根，`ctx.factors(合约)` 是事实面板的字段（资金费、OI 变化等；回放里没有，按 NaN 处理）。

脚本是一个纯函数：每次检查都从 K 线重新算，两次检查之间不保留任何东西。这样回放看到的和实盘检查一模一样。

## 限制

- 只能导入 `ctg`、`numpy`、`math`、`statistics`、`collections`、`itertools`、`functools`、`typing`；不能读写文件、不能联网（运行在没有网络的策略容器里）。
- 脚本不超过 8000 字节；每次检查有 CPU 时间预算（默认 200 毫秒），平均超过 50 毫秒的脚本不接受。
- 同时最多 10 个脚本信号；一个订阅里最多一个脚本，可以和内置条件放在“全部满足 / 任一满足”里。
- 检查间隔不能选“实时”：脚本在它的 K 线收盘时运行。检查间隔比周期慢时，按检查间隔来（比如 5m 周期、每 15 分钟检查，就在每个 15 分钟整点运行）。

## 订阅前的检验（测试）

点「测试」或订阅时，服务器先编译脚本，再把它在最近 7 天的每根 K 线收盘上跑一遍（连同 lookback 最多 1000 根：lookback 200 时 1m 周期约 13 小时，5m 约 2.8 天），告诉你：

- 会触发几次、每天几次、每次的时间和数值；
- 有没有出错、平均和最慢耗时；
- 现在是否已经成立。

以下情况不接受，并说明原因：编译出错、回放中出错或超时、太慢、每天触发超过 6 次（多半是条件太松）、最新一根判断不了、现在已经成立（订阅只在变为成立时触发：现在就行动，或把条件收紧）。

## 运行中出错

脚本连续 3 次出错（抛异常、超时、让执行进程崩溃）时，订阅自动结束，状态为已取消，原因里写着最后一次的错误，并推送通知。缺少 K 线、执行环境暂时不可用不算脚本的错：这次检查记为“无结论”，信号详情里能看到原因；执行环境连续 30 分钟不可用会推送一次。
