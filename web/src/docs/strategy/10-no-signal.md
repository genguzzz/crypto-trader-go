# 为什么没有信号 / 信号为什么没成交

先分清是哪一种：

- **没有信号**：信号列表里什么都没有。问题在策略或实例本身。
- **有信号但没成交**：信号列表里有，去向不是“已下单”，或者已下单但没有成交。问题在信号处理流程或账户规则。

## 排查清单

按顺序检查，大多数问题在前三步就能找到。

1. **实例状态**。卡片上应该是“运行中”。
   - 未启动 / 已停止：点启动。
   - 已暂停：看暂停原因。如果是 `策略连续 3 次处理异常，已暂停：…`，先看运行日志里的错误。代码问题：改代码、发布新版本，用新版本新建实例（已有实例固定在创建时的版本）；偶发的数据问题：直接点继续。
   - 故障：进程超时（单个事件超过 5 秒）或崩溃，会自动重启，最多 3 次，再故障就停止：`连续故障 3 次后停止：…`。正常运行满 10 分钟后的故障重新从第 1 次算。
   - `等待策略运行器连接`：策略运行服务没在运行，不是你的代码问题。
2. **卡片上的状态行**（策略的 `status()`）。写得好的策略会告诉你它在等什么：“等下一次交叉”“离快线太远，等回落”“观察名单为空”。没写 `status()` 的策略，建议先补上。
3. **运行日志**。看有没有 `error`（处理函数抛异常）和 `warn`：
   - `signal open_long … dropped: cannot resolve stopLoss '2atr': ATR(14) unavailable`：历史 K 线不够，算不出 ATR，信号没有发出去。
   - `signal … refused: …`：信号格式被拒（比如数值为负）。
   - `ctx.state not saved: …`：状态超过 64 KB 或含有不能转 JSON 的东西。
4. **执行方式**。“只记录”永远不会下单，信号去向都是“只记录”。
5. **周期**。4H 策略一天只有 6 次机会，1D 策略一天 1 次（UTC 0 点）。刚建好的实例要等到下一个整周期收盘才第一次运行。
6. **入场条件本身有多罕见**。用 [试运行](/help/strategy/backtest-trial) 跑最近 30–60 天，数一数出了几个信号。如果 60 天里只有 2 个，实时等上几周没信号是正常的。
7. **数据**。新上市的币历史不够，`len(b)` 达不到要求就会一直跳过；动态池（Screener）的标的可能是空的。
8. **信号列表里的去向和原因**。对照下面的表。

## 信号去向是“风控拒绝”时

| 原因 | 意思 | 怎么办 |
|---|---|---|
| `实例未运行（paused）` 等 | 信号发出时实例不在运行（比如暂停时 `on_fill` 里发的） | 恢复实例 |
| `合约不存在或已下线` | 合约代码写错，或已下架 | 检查 `universe` 和信号里的合约名 |
| `减仓比例 reduceFrac 需在 (0, 1]` | `Signal.reduce` 的比例不对 | 改成 0 到 1 之间 |
| `策略声明了不做空（can_long / can_short）` / `…不做多…` | 策略类声明了 `can_short = False`（或 `can_long = False`），却发出了这个方向的开仓信号 | 开仓前用 `self.allows(side)` 判断；确实要做这个方向就改类声明并发布新版本 |
| `该合约已有待处理信号 #N` | 同一合约上一个信号还在等 AI 或人工确认 | 一个事件对同一合约只发一个信号；反手用 `.reversed()` |
| `日内熔断：今日（UTC+8）不再开仓` | 今天亏损已达账户的日亏损熔断比例 | 北京时间次日 0 点自动恢复；平仓不受影响 |
| `冷却中：BTC 平仓后 30 分钟内不再开仓` | 该合约（账户内任何实例）刚平过仓 | 等冷却结束；反手用 `.reversed()` 不受限制；或在账户设置里调短冷却 |
| `账户要求开仓信号带止损` | 开仓信号没有 `stop_loss` | 加上止损 |
| `止盈价 … 位于参考价 … 的错误一侧` | 做多止盈低于现价，或做空止盈高于现价 | 检查方向；用 `"4atr"` 这类写法可避免 |
| `止损价 … 位于开仓价 … 的错误一侧` | 做多止损高于现价，或做空止损低于现价 | 同上；也可能是价格已经越过了你写死的止损价 |
| `已有反向持仓，请先平仓` | 本实例持有反方向仓位，信号没带反手 | 用 `.reversed()`，见 [做空与反手](/help/strategy/short-reverse) |
| `账户内另一实例持有反向仓位` | 同账户别的实例持有该合约的反方向仓位 | 一个合约在一个账户里只能有一个方向；把策略放到不同账户 |
| `持仓数已达上限 5` | 账户（所有实例合计）的持仓数到了上限 | 调高账户的最大持仓数，或在策略里先判断 |
| `止损距离过大：1 倍杠杆下强平价也在止损之前` | 做空时止损离得太远 | 收近止损 |
| `可用保证金不足或已达单合约上限 30%` | 没钱了，或该合约占用的保证金已到上限 | 减少同时持仓，或调整账户规则 |
| `按风险计算的数量 0.004 张低于最小下单量 0.01 张` | 止损太远或权益太小，算出的数量不够一手 | 收近止损、提高 `strength` 或账户的单笔风险 |
| `加仓止损过远：需要低于现有 …x 的杠杆` | 同方向加仓时，新止损要求的杠杆比现有持仓低 | 加仓前判断是否已有仓位，或收近止损 |
| `缺少价格或合约面值` / `无有效价格` / `无行情：…` | 拿不到价格 | 通常是行情暂时中断，等待即可 |
| `无持仓` | 发了平仓 / 减仓，但本实例在该合约没有仓位（可能已被止损） | 平仓前先判断 `ctx.position(inst)` |
| `已有待成交的平仓单` | 上一个平仓单还没成交 | 不用重复发平仓 |
| `减仓数量低于最小下单量` | 持仓太小，按比例减不出一手 | 用 `Signal.close` 全平 |
| `反手被拒：…` | 反手前检查发现新方向开不了（比如熔断、没带止损），所以旧仓位**没有动** | 看后面的具体原因 |
| `反手开仓被拒：…` | 反手的平仓成交了，但开新仓时算仓位被拒（数量太小、保证金不足等），结果只平了仓 | 看后面的具体原因 |
| `下单失败：…` / `成交失败：…` | 系统内部错误 | 看服务日志 |

## 其他去向

| 去向 | 原因 | 怎么办 |
|---|---|---|
| 过期 | `信号已超过有效期`、`等待审核/确认期间超过有效期`、`AI 审核超时` | 确认要及时；或给信号设更长的 `ttl_ms` |
| AI 跳过 | AI 的理由；`AI unavailable`（未授权或不可用）；`AI 错误：…` | 看理由；AI 不可用时改用“自动”执行 |
| 用户跳过 | `人工跳过（…）`：你选了跳过，或确认超时且默认是跳过 | 调整账户的确认设置 |
| 只记录 | `仅记录模式` | 把执行方式改成“自动”或“AI 审核” |

## “已下单”却没有成交

“已下单”只说明通过了风控。之后：

- **实时**：市价单按盘口吃单，只吃滑点容忍（默认 10 bp）以内的价格。吃不到就撤销，原因写在信号的详情里：`未成交：无满足滑点上限（…）的对手价`；只吃到一部分时剩余撤销：`IOC 剩余撤销（滑点上限内深度不足）`。冷门币盘口薄时常见，可以给信号设更大的 `max_slippage_bp`。
- **回测**：在下一根基础 K 线开盘成交；开盘价超出滑点容忍时撤单：`开盘价超出滑点上限（…）`。

## 案例：大币均线趋势几周都不开仓

内置策略 `majors-trend`（BTC / ETH 4H，EMA20 / EMA50）有两种入场方式：

- `state`（方向成立即入场）：快线在慢线上方、手里没仓位，就在下一根收盘入场（价格离快线太远时先等回落）。
- `cross`（只在交叉那根入场）：**只在 EMA20 刚刚穿过 EMA50 的那一根 4H K 线**入场。

`cross` 方式的问题在于交叉很少见。以最近为例：BTC 和 ETH 的上一次交叉都发生在 2026-09-18 20:00 UTC，之后 14 天里一次都没有。在那之后新建的 `cross` 实例，可能要等好几周才第一次开仓。实例刚建、暂停、重启时错过了交叉那一根，同样要等下一次。这不是故障，是这个入场方式本来的样子。所以现在的默认值是 `state`。

旧版本还有一个真正的问题：方向反转时它先发平仓，再在 `on_fill` 里发开仓。平仓一成交，账户的 30 分钟冷却就开始了，开仓信号总是被拒（`冷却中：…`），结果只平仓不反手。现在的版本改用一步反手 `Signal.reversed()`，开仓那一半不受冷却限制。

怎么一眼看出它在等什么：卡片上的状态行，例如

```
BTC 快线在上 +1.25%，等下一次交叉；ETH 快线在下 -0.40%，持空
```

`等下一次交叉` 说明是 `cross` 方式在等；`离快线太远，等回落` 说明是 `state` 方式的追高保护；`下一根收盘入场` 说明条件已经满足。写你自己的策略时，也让 `status()` 把“差什么条件”写出来，排查会轻松很多。
