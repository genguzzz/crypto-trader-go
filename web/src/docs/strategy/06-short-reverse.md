# 做空与反手

永续合约做空和做多一样简单：价格下跌时空单赚钱。做空信号的写法、止损止盈、仓位计算都和做多对称。

## 开空单

```python
Signal.open_short(inst, stop_loss="2atr", take_profit="4atr", reason="EMA 下穿")
# 等价写法
Signal.open(inst, "short", stop_loss="2atr", take_profit="4atr", reason="EMA 下穿")
```

做空时 `"2atr"` 止损会被换算到参考价**上方**，止盈在下方。直接写价格时要自己保证方向正确，否则会被拒绝：

- 止损在错误一侧 → `止损价 … 位于开仓价 … 的错误一侧`
- 止盈在错误一侧 → `止盈价 … 位于参考价 … 的错误一侧`

## 控制能不能做空

有三层：

| 层 | 写法 | 作用 |
|---|---|---|
| 类属性 | `can_short = False` | 声明策略不做空：显示在策略卡片上，`allows("short")` 永远返回 False，**订单层也会拒绝**它的开空信号 |
| 方向参数 | `direction = Choice("both", ["both", "long", "short"], ...)` | 让每个实例自己选；`allows()` 会读它，但订单层不知道它 |
| 代码判断 | `if self.allows(side): ...` | 在策略里提前拦住，不发出注定被拒或不想要的信号 |

订单层的规则：策略至少声明了一个方向时，开它没声明的方向会被拒绝，原因是 `策略声明了不做空（can_long / can_short）`（或 `不做多`）。`can_long` 和 `can_short` 都写 False 的策略（比如只发通知、不交易的）不受这条限制。

`direction` 参数只靠 `allows()` 生效，所以模式是：

```python
direction = Choice("both", ["both", "long", "short"], labels=["多空双向", "只做多", "只做空"],
                   group="风控", label="方向")

def on_bar(self, ctx, bar):
    want = "long" if ... else "short"
    if not self.allows(want):
        return None
    return Signal.open(bar.inst, want, stop_loss="2atr")
```

“只做多”时遇到看空信号怎么办，取决于策略：大币均线趋势选择“把多单平掉、不开空单”，见 [内置策略讲解](/help/strategy/builtins)。

## 一个合约只能有一个方向

账户里同一个合约**只能持有一个方向**：

- 本实例已持有多单，再发开空信号（不带反手）→ `已有反向持仓，请先平仓`
- 同账户的另一个实例持有多单，本实例想开空 → `账户内另一实例持有反向仓位`

这是账户级规则，两个策略在同一个账户里对同一个合约看法相反时，后来的那个开不了仓。需要同时跑多空观点相反的策略，就把它们放在不同账户里。

## 反手：从多翻成空

趋势策略经常需要“平掉多单，立刻开空单”。有两种写法。

### 推荐：Signal.reversed()

```python
sig = Signal.open(bar.inst, "short", stop_loss="2atr", reason="EMA 下穿")
if ctx.position(bar.inst) is not None:
    sig = sig.reversed()
return sig
```

`.reversed()` 只能用在开仓信号上。订单层收到后：

1. 本实例在该合约持有**反方向**仓位时：先市价平掉它，平仓成交后立刻按新方向开仓（实时是同一时刻；回测里平仓和开仓都在下一根开盘价成交）。
2. 没有反方向仓位时：就是一个普通开仓信号。

所以可以放心地总是加上 `.reversed()`，不必先判断有没有反向仓位。

反手时的规则检查：

- **不受冷却限制**（见下文），本实例自己的反向仓位当然也不算冲突。
- **平仓之前**先检查新方向能不能开：熔断、必须带止损、止盈方向、同账户其他实例的反向仓位、持仓数上限。不能开就**什么都不做**，旧仓位保留，信号被拒，原因是 `反手被拒：<具体原因>`，比如 `反手被拒：日内熔断：今日（UTC+8）不再开仓`。
- 平仓成交后开新仓时才算仓位大小，这一步还可能因为数量太小、保证金不足等被拒，结果就是只平了仓：实时运行时这个信号的结果仍是 `ordered`，原因末尾附上 `反手开仓被拒：…`；回测里会额外收到一条结果为 `rejected`、原因以 `反手开仓被拒：` 开头的 `on_signal_result`。

平掉旧仓的那笔成交会触发 `on_fill` 和 `on_position_closed`（`kind` 为 `fill`），随后新仓的成交再触发一次 `on_fill`。

### 不推荐：先平仓，再在 on_fill 里开仓

```python
# 旧写法，不要这样做
def on_bar(self, ctx, bar):
    return Signal.close(bar.inst, reason="趋势反转")

def on_fill(self, ctx, fill):
    if ...:
        return Signal.open_short(fill.inst_id, stop_loss="2atr")
```

问题在于**冷却**：账户规则默认“某合约平仓后 30 分钟内不再开仓”。平仓刚成交，开仓信号就会被拒：`冷却中：BTC 平仓后 30 分钟内不再开仓`。旧版大币均线趋势就是这么写的，所以它的反手从来没成功过，只平仓不开仓。

也不能在同一个事件里返回 `[Signal.close(...), Signal.open_short(...)]`：同一合约同时只能有一个待处理信号，第二个可能被拒；就算没被拒也会撞上冷却。

## 冷却规则的细节

| 项 | 规则 |
|---|---|
| 时长 | 账户设置“冷却时间”，默认 30 分钟，0 表示不冷却 |
| 什么时候开始 | 某合约的持仓**完全平掉**的那一刻：信号平仓、止损、止盈、持仓到期、强平都算 |
| 范围 | 整个账户、按合约：任何实例平掉 BTC，账户里所有实例 30 分钟内都不能开 BTC |
| 例外 | `reversed()` 反手的开仓那一半不受限制 |

冷却是为了防止止损后马上又追进去反复挨打。如果你的策略本来就设计成高频进出，可以在账户设置里调短。

## 做空要多注意的地方

- **资金费**：资金费率为正时，空单收钱、多单付钱，反之亦然。持仓结算时会调用 `on_funding(ctx, inst, rate, amount)`，`amount` 为负表示付出。可以用 `ctx.series(inst, "funding")` 查看历史费率。
- **追踪止损**对空单同样有效：记录持仓以来的最低价，止损 = 最低价 + 距离，只往下移。
- 状态显示要说清楚方向，比如 `持空，止损 61,200`，方便你看卡片时一眼明白。
