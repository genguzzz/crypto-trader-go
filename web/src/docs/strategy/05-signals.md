# 信号、止损止盈与仓位计算

策略唯一能做的“动作”是发出 **Signal**。信号说的是“意图”：在哪个合约、做什么、止损在哪。下多少、能不能下，由账户的订单层决定。

## 四种信号

```python
from ctg import Signal

Signal.open_long("BTC-USDT-SWAP", stop_loss="2atr", take_profit="4atr", reason="EMA 上穿")
Signal.open_short("BTC-USDT-SWAP", stop_loss="1.5%", reason="跌破支撑")
Signal.open("BTC-USDT-SWAP", "long", stop_loss=58000)      # side 是 "long" 或 "short"
Signal.close("BTC-USDT-SWAP", reason="趋势结束")             # 平掉本实例在该合约的全部持仓
Signal.reduce("BTC-USDT-SWAP", 0.5, reason="减半")          # 减掉一半，比例在 (0, 1]
```

`open_long` / `open_short` 和 `open` 的参数顺序不完全一样，**请一律用关键字参数**（`stop_loss=...`）。

开仓信号的全部字段：

| 字段 | 默认 | 说明 |
|---|---|---|
| `stop_loss` | 无 | 止损：价格、`"<k>atr"` 或 `"<k>%"`。账户默认要求必须有 |
| `take_profit` | 无 | 止盈，写法同上 |
| `trailing_stop` | 无 | 追踪止损的**距离**：价格差、`"<k>atr"` 或 `"<k>%"` |
| `time_limit` | 无 | 持仓时限：`"30m"` `"6h"` `"1.5h"` `"2d"`，或毫秒数。到点由订单层平仓 |
| `strength` | `1.0` | 信号强度 (0, 1]，按比例缩小仓位 |
| `leverage` | 账户上限 | 想要的杠杆，会被账户和合约上限截断 |
| `max_slippage_bp` | 账户的滑点容忍 | 市价入场最多偏离参考价多少 bp |
| `ttl_ms` | 300000（5 分钟） | 有效期，超过还没处理完就作废 |
| `reason` | `""` | 理由，显示在信号列表和通知里（最多 500 字符）。**一定要写** |

`close` 和 `reduce` 只有 `reason` 和 `ttl_ms`。另外开仓信号可以 `.reversed()` 变成一步反手，见 [做空与反手](/help/strategy/short-reverse)。

## 止损止盈的三种写法

| 写法 | 例子 | 含义 |
|---|---|---|
| 价格 | `stop_loss=58000` | 就是这个价格 |
| ATR 倍数 | `stop_loss="2atr"`、`"2.5atr"` | 参考价 ∓ k × ATR(14)，ATR 按实例周期计算 |
| 百分比 | `stop_loss="1.5%"` | 参考价 ∓ 参考价 × k% |

- **参考价**：信号在 K 线事件里发出时，是该合约这根 K 线的收盘价；在其他事件（定时器、成交）里发出时，是实例周期最新一根已收盘 K 线的收盘价。
- 方向自动处理：做多时止损在参考价下方、止盈在上方，做空相反。
- 价格最后会按合约的最小价格变动取整。
- 写法错误（比如 `"2 ATR%"`）或 ATR 算不出来（历史不够）时，信号**不会发出**，运行日志里会有一条 `signal … dropped: …` 警告。

注意：实际成交价和参考价会有差别（实时按盘口成交，回测在下一根开盘价成交），所以 ATR / 百分比换算出的止损价是**以参考价为准**的固定价格，不会随成交价再调整。

## 止损止盈怎么执行

开仓成交后，订单层马上为整个持仓挂上止损单和止盈单（二者互斥，一个成交另一个撤销）。

- **实时**：大约每 1.5 秒检查一次最新价，触发后按市价成交（不受滑点容忍限制）。
- **回测**：用每根基础 K 线的最高价 / 最低价判断。同一根里止损和止盈都碰到时，按**先止损**处理（偏保守），除非开盘就跳空越过了止盈。跳空越过止损时按开盘价成交。
- **追踪止损**：记录持仓以来的最有利价格，止损 = 最有利价 − 距离（做空则 +）。**只收紧不放松**。回测里从下一根 K 线开始移动。
- **持仓时限**：从第一次开仓成交算起，到点按市价平仓，平仓原因是“持仓到期”。加仓不会延长时限。

同方向再发开仓信号就是**加仓**：仓位按新信号再算一份，止损止盈换成新信号的（新信号没写的沿用旧的），覆盖整个持仓。不想加仓就先判断 `ctx.position(inst) is None`。

## 仓位怎么算

仓位由止损距离决定：**止损被打到时，亏掉的钱 = 权益 × 单笔风险 × 强度**。

```
数量（张）= 权益 × 单笔风险 × 强度 × 缩放 ÷ (|参考价 − 止损价| × 合约面值)
```

- **参考价**：下单那一刻的价格。实时是当时盘口的中间价，回测是最近一根基础 K 线的收盘价。（它和上面换算止损用的 K 线收盘价可能略有不同。）
- **单笔风险**：账户规则，默认 1%。
- **强度**：信号的 `strength`。
- **缩放**：人工确认选“半仓”时是 0.5，AI 审核可以给出更小的比例；否则是 1。
- **合约面值**：每张合约是多少个币（`ctx.spec(inst).ct_val`）。

然后依次受这些约束：

1. **杠杆**：用信号的 `leverage`，没写或超过账户上限（默认 5x）就用账户上限，再受合约上限约束；还会自动降低杠杆，保证强平价在止损价外侧至少再留出止损距离的 25%。
2. **保证金上限**：这笔占用的保证金 ≤ min(可用资金 × 98%，权益 × 单合约上限 − 该合约已占用的保证金)。单合约上限默认 30%。超出就把数量削到上限。
3. **取整**：按合约的下单步长向下取整，低于最小下单量就拒绝。

**例子**：权益 10,000 USDT，单笔风险 1%，强度 1，BTC 参考价 60,000，止损 58,800（距离 1,200），面值 0.01 BTC/张：

```
数量 = 10000 × 1% × 1 ÷ (1200 × 0.01) ≈ 8.33 张 → 名义价值约 5,000 USDT
5 倍杠杆下保证金约 1,000 USDT，没超过 10000 × 30% = 3,000，不用削
```

止损打到时亏 8.33 × 0.01 × 1,200 ≈ 100 USDT，正好是权益的 1%（另加手续费和滑点）。

所以：**止损越远，仓位越小**；想轻仓试探就把 `strength` 调小，而不是把止损放远。

没有止损（账户关闭了“必须带止损”）时：保证金 = 权益 × 单合约上限 × 强度 × 缩放。

## 信号的处理流程

```
策略发出信号
  → 基本校验（实例在运行、合约存在、减仓比例合法、方向符合策略的 can_long / can_short 声明）
  → 有效期检查
  → 执行方式是“只记录”？→ 记录后结束
  → 同一合约已有待处理信号？→ 拒绝
  → 执行方式是“AI 审核”且是开仓？→ AI 判断执行 / 跳过（可缩小仓位、改止损止盈）
  → 账户开启人工确认？→ 等你选 执行 / 半仓 / 跳过
  → 再次检查有效期
  → 账户规则检查 → 计算仓位 → 下单
```

AI 审核和人工确认只在实时账户进行，回测和试运行里跳过。

**同一合约同时只能有一个待处理信号**：上一个信号还在等 AI 或等你确认时，同一实例对同一合约的新信号会被直接拒绝。所以一个事件里对同一个合约只发一个信号——比如反手不要返回 `[close, open]` 两个，而是用 `.reversed()`。

**有效期（TTL）**：默认 5 分钟，从信号发出（K 线收盘）算起。等 AI 或等确认超过有效期就作废。确认超时时间（默认 120 秒）也不会超过信号有效期。

## 信号的去向

每个信号最后都有一个结果，会通过 `on_signal_result(ctx, result)` 告诉策略，也显示在信号列表里：

| outcome | 页面显示 | 含义 |
|---|---|---|
| `pending` | 等待中 | 正在等 AI 或人工确认 |
| `ordered` | 已下单 | 通过风控并下了单。**不等于已成交**，见下 |
| `rejected` | 风控拒绝 | 被校验或账户规则拒绝，`reason` 写明原因 |
| `skipped_ai` | AI 跳过 | AI 判断不执行，或 AI 不可用 |
| `skipped_user` | 用户跳过 | 你在确认时选了跳过，或确认超时且默认是跳过 |
| `expired` | 过期 | 超过有效期 |
| `recorded` | 只记录 | 实例的执行方式是“只记录” |

“已下单”之后仍可能没成交：实时按盘口吃单，在滑点容忍内吃不到就撤销（原因里会写“未成交：无满足滑点上限……的对手价”）；回测在下一根开盘价成交，开盘价超出滑点容忍也会撤销。成交了会收到 `on_fill`。

每种拒绝原因的含义和解决办法，见 [为什么没有信号](/help/strategy/no-signal)。

```python
def on_signal_result(self, ctx, result):
    if result.outcome not in ("ordered", "recorded", "pending"):
        ctx.log(f"信号 #{result.signal_id} {result.outcome}：{result.reason}", level="warn")
```
